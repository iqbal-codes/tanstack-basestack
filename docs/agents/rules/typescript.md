# TypeScript Rules

## Purpose

Controls type safety, module conventions, and compiler strictness for this TanStack Start project.

## When To Read This

- Writing any `.ts` or `.tsx` file.
- Reviewing a PR that adds types, imports, or generic patterns.
- Debugging a `tsc --noEmit` failure.

## Current Project Pattern

TypeScript configuration lives at `tsconfig.json`:

- `strict: true`, `noUnusedLocals: true`, `noUnusedParameters: true`, `verbatimModuleSyntax: true`
- Bundler module resolution (`moduleResolution: "bundler"`)
- `"#/*"` maps to `"./src/*"` in both `tsconfig.json` paths and `package.json` imports
- `@/*` is an alias for `./src/*` used by shadcn/ui components (`components.json`)

Generated file `src/routeTree.gen.ts` uses `as any` type casts once per route to compose generated route objects — this is expected for generated code and excluded from Biome checks.

## Non-Negotiable Rules

- MUST use `verbatimModuleSyntax`-compliant imports (no `import React` unless needed).
- MUST use `#/` prefix for all internal imports (e.g. `import { db } from '#/db/index'`).
- MUST NOT use `any` in authored source. Exceptions: see allowed exceptions below.
- MUST NOT use `unknown` in authored source, except when narrowing at an external boundary.
- MUST NOT use non-null assertions (`!`).
- MUST prefer explicit type annotations on function return types over relying on inference for exported functions.
- MUST use `type` imports for type-only bindings (e.g. `import type { Product } from '#/features/products/model'`).
- MUST use `const` assertions where appropriate (e.g. `supportedLocales = ['en', 'id'] as const` in `src/messages/index.ts`).

## Allowed Exceptions

- `as any` in `src/routeTree.gen.ts` — this file is autogenerated by `@tanstack/router-plugin` and must not be authored manually.
- `Record<string, unknown>` in TanStack Router route context extraction — see `src/routes/_protected.tsx:46-49` for how `leafMatch.context` is cast; this is unavoidable for type-safe route context decoration and per TanStack Router design.
- `as SQL` in Drizzle query building when the ORM's type inference doesn't narrow union condition types.
- `catch (err: unknown)` is OK at external boundaries, but the value MUST be narrowed to `Error` or `string` before use.

## Implementation Checklist

1. Ensure every new `.ts`/`.tsx` file uses `#/` imports.
2. Ensure every exported function has an explicit return type.
3. Ensure no `any` or `unknown` appears in new authored code.
4. Run `bun run typecheck` before marking any feature complete.

## Verification

```
bun run typecheck
```

## Common Mistakes To Avoid

- Using `// eslint-disable` or `// biome-ignore` to silence type errors — fix the type instead.
- Casting Drizzle return values with `as` inside user-facing components — do that work once in feature models.
- Importing types with the same specifier as values when `verbatimModuleSyntax` requires `import type`.
- Copy-pasting patterns from `src/routeTree.gen.ts` into authored source.
